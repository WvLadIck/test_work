# Расчёт продаж по дням и артикулам

Скрипт читает выгрузку заказов и создаёт `daily_by_sku.csv`. В `orders` входят все уникальные заказы, включая отменённые. В `revenue` — сумма `quantity × price` только для выкупленных заказов (`delivered`). Результат отсортирован по артикулу, затем по дате.

## Запуск

В текущем репозитории представлен уже полностью готовый пример скрипта с конечным результатом. Скрипт уже отработал на "Данные для тестового задания".

Нужен Python 3.10 или новее. Сторонних библиотек нет, устанавливать зависимости не требуется. Проверено на Python 3.14.2.

Положите в папку репозитория выгрузку под именем `sales.csv`
Откройте терминал в папке репозитория и выполните:

```bash
python calculate_sales.py
```

Файл `daily_by_sku.csv` появится в текущей папке. При повторном запуске он перезаписывается. Исходный файл не меняется.

Можно указать другое имя или путь. Например, если файл лежит на одну папку выше:

```bash
python calculate_sales.py "../sales.csv"
```

Другой путь для результата задаётся через `-o`:

```bash
python calculate_sales.py sales.csv -o result.csv
```

Входной CSV: UTF-8 (также поддерживается BOM), разделитель — запятая. Обязательные колонки: `order_id,order_date,sku,quantity,price,status`. Порядок колонок может отличаться. В цене используется десятичная точка. Выходной CSV записывается в UTF-8 с колонками `sku,order_date,orders,revenue`.

## Обработка данных

В исходной выгрузке 13 858 строк без заголовка. Найдены:

| Проблема | Количество строк | Решение |
|---|---:|---|
| Полностью одинаковые повторы | 60 лишних строк | Учитывается один экземпляр |
| Пробел после `delivered` | 11 | Пробелы по краям значений удаляются |
| Статусы с заглавными буквами | 21 | Статусы приводятся к нижнему регистру |
| `canceled` вместо `cancelled` | 3 | Заменяется на `cancelled` |
| Пустое `quantity` | 4 | Все эти заказы отменены: входят в количество заказов с нулевой выручкой |

Количество и цену отменённых заказов не проверяю: для этих показателей они не нужны. Пропуски не заменяются выдуманными значениями.

Повторы сравниваются после исправления пробелов и статусов. Если один `order_id` встречается с разными данными, скрипт останавливается: по этой выгрузке нельзя определить, какая версия правильная. Таким образом, предполагается одна строка на заказ; заказы с несколькими разными товарами под одним номером требуют отдельного правила.

Неизвестные статусы, пустые номер заказа или артикул, неверные даты и некорректные количество или цена для `delivered` вызывают ошибку с номером строки. Количество должно быть целым положительным числом, цена — конечным неотрицательным числом с точностью до копеек. Неоднозначные опечатки автоматически не исправляются.

Расчёт выполняется до открытия выходного файла. Если найдена ошибка в данных, новый результат не записывается, а существующий файл результата остаётся прежним. Деньги считаются через `Decimal`, чтобы избежать погрешности `float`.

## Проверка результата

Скрипт запущен на полной выгрузке. Расчёт независимо повторён средствами PowerShell: удаление повторных номеров заказов, группировка по артикулу и дате, сумма количества товаров, умноженного на цену, только для выкупленных заказов. Сравнены все 631 строки результата — расхождений нет.

| Контрольный показатель | Результат |
|---|---:|
| Уникальные заказы | 13 798 |
| Выкупленные заказы | 12 047 |
| Отменённые заказы | 1 751 |
| Общая выручка | 10 276 540,00 руб. |
| Пары «артикул — день» | 631 |
| `UYT-0001`, 2026-08-17 | 28 заказов, 27 650,00 руб. |

На небольших контрольных примерах дополнительно проверены: дубль заказа, исправление статусов, отмена с пустыми количеством и ценой, точный расчёт `3 × 0.10 = 0.30`, неизвестный статус, неверная дата, пустой артикул, некорректные числа и конфликтующие версии заказа. CSV только с заголовком даёт пустой набор показателей. Проверки выполнялись отдельно; дополнительные тестовые файлы в решение не включены.

## Использование ИИ и ограничения

Использован ChatGPT (Codex) для анализа выгрузки, написания скрипта, проверок и оформления README. Правила обработки данных согласованы в обсуждении: одинаковые дубли пропускать, однозначные опечатки исправлять, пропуски не угадывать.

При первом анализе PowerShell объединил статусы с разным регистром, поэтому варианты `Delivered`, `DELIVERED`, `Cancelled` и `CANCELLED` не были видны отдельно. Первый запуск Python выявил эту проблему. После этого добавлено приведение статусов к нижнему регистру и повторены проверки.

Расчёт и README готовы. История коммитов и отправка репозитория остаются отдельным шагом подготовки к сдаче. Скрипт хранит уникальные заказы в памяти; для предоставленной выгрузки этого достаточно. Поддержка других форматов выгрузки и неоднозначных исправлений не реализована.
